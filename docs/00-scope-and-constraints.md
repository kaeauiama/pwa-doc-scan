# pwa-doc-scan — スコープ・非目標・制約(正典)

最終更新: 2026-08-24 / 状態: M0 確定

この文書が正。他文書と矛盾する場合はこちらを優先する。

---

## 1. 目的

紙の書類をスマートフォンで撮影し、**読みやすいモノクロ**で**適切なファイルサイズ**の
PDF として保存する。iPhone / Android の両方で、インストール不要・課金なし・
透かしなし・オフライン完結で動く。

想定利用者は kaoya さん本人。マルチユーザ・配布・収益化は当面考えない。

## 2. なぜ native ではなく PWA か

1. **無音撮影**。`getUserMedia` 経由のフレーム取得は OS の静止画撮影パスを通らないため、
   日本版 iPhone でもシャッター音が鳴らない。native アプリでは達成できない(HC-1/HC-2 の
   制約下でのみ利用する)。
2. **配布と更新が自由**。審査・ストア・署名が要らない。
3. **完全ローカル**。サーバを持たないことを構造的に保証しやすい。

トレードオフは解像度(§6 L-1)。これは二経路併存(REQ-01)で受ける。

## 3. 要件

### 機能要件

| ID | 要件 | M |
|---|---|---|
| REQ-01 | 撮影経路は `getUserMedia` + canvas の一本(無音)。別に「**写真から読み込む**」動線を持ち、撮影済みの画像ファイルを同じパイプラインに通せる(D-020) | M1 |
| REQ-02 | ライブ映像上で書類の四辺を**自動検出**し、四隅をオーバーレイ表示する(検出ロジックは実装済み。オーバーレイ表示は未着手) | M1 |
| REQ-03 | 検出された四隅を手動でドラッグ修正できる。自動検出が失敗した場合も手動で完遂できる | M1 |
| REQ-04 | 四隅から射影変換(homography)で台形補正し、矩形に正規化する | M1 |
| REQ-05 | 局所適応二値化(Sauvola 系)でモノクロ化する。照明ムラ・影に耐えること | M1 |
| REQ-06 | 出力は **1bit 画像を FlateDecode で埋めた PDF**。自前生成し、外部ライブラリに依存しない | M1 |
| REQ-07 | 保存は **共有シート**(`navigator.share({files})`)を主動線とする。副動線として `<a download>` を用意する | M1 |
| REQ-08 | オートキャプチャ(枠が安定したら自動シャッター)。ON/OFF 可能 | M2 |
| REQ-09 | ブレ検出(Laplacian 分散)。閾値未満なら警告し、オートキャプチャを抑止する | M2 |
| REQ-10 | 複数ページを 1 つの PDF にまとめる。順序変更・ページ削除ができる | M3 |
| REQ-11 | 出力 DPI と用紙サイズを選べる(既定 A4)。プリセット「メール添付 / 保存版」を持つ | M3 |
| REQ-12 | 傾き補正(deskew)、グレースケール出力モード | M4 |
| REQ-13 | オフラインで全機能が動く(Service Worker で precache) | M1 |
| REQ-14 | 非対応・失敗は**理由コード**とともに画面に出す(例: `UNSUPPORTED_NO_CAMERA`, `UNSUPPORTED_NO_SHARE_FILES`, `DEGRADED_LOW_RESOLUTION`) | M1 |
| REQ-15 | 診断画面を持つ。実測した解像度・利用可能 API・失敗履歴を確認できる | M1 |
| REQ-16 | カメラは起動時に自動で開かず、明示操作で開始する。権限が起動ごとに聞かれることを UI で説明する(D-023) | M1 |
| REQ-17 | manifest を出し `display: standalone` を宣言する。standalone 判定は `navigator.standalone` を優先する(D-022) | M1 |
| REQ-18 | プレビューは低解像度、シャッター時のみ最大解像度に切り替える(D-021、実測待ち) | M1 |
| REQ-19 | torch(ライト)の ON/OFF を撮影 UI に置く。非対応端末では出さない | M2 |

### 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 撮影→PDF 生成完了まで、1 ページあたり **3 秒以内**(iPhone 実機、A4 300dpi 相当) |
| NFR-02 | 初回ロードの総転送量 **3MB 以内**(OpenCV.js カスタムビルド込み) |
| NFR-03 | A4 1 ページの PDF が **100KB 以内**。200dpi 出力なら実測 43〜51KB で満たす。300dpi はノイズが多いと超えうる(10-platform-findings §6) |
| NFR-04 | コア処理(二値化・射影変換・PNG/PDF エンコード)は**依存ゼロの純粋関数**として実装し、単体テストを持つ |
| NFR-05 | ネットワークリクエストは静的アセットの取得のみ。実行時に外部へ出る通信を持たない |

## 4. 非目標(やらない)

| ID | 非目標 | 理由 |
|---|---|---|
| NG-01 | OCR / テキスト抽出 | 実装コスト(Tesseract.js 数MB・低速)に対し、当面の用途で必要性が薄い。M4 以降で再検討 |
| NG-02 | クラウド同期・アカウント・サーバ | HC-3 に抵触。構造的に持たない |
| NG-03 | 本の見開き湾曲補正(vFlat 相当) | 難度が高く、対象が平らな書類なので不要 |
| NG-04 | 名刺・レシートの自動仕分け、帳票認識 | スコープ外 |
| NG-05 | 動画撮影・録音 | 用途外。音声トラックは一切要求しない |
| NG-06 | ネイティブアプリ化(Capacitor 等でのラップ) | シャッター音強制の対象になり、PWA を選んだ理由が消える |

## 5. Hard Constraints(恒久・例外は承認制)

| ID | 制約 | 担保方法 |
|---|---|---|
| **HC-1** | 用途は書類・紙面のスキャンに限定する。人物撮影向けの機能・UI・訴求を持たない | ドキュメント + 初回起動時の用途表示 |
| **HC-2** | 隠し撮りを容易にする機能は恒久的に非対応。具体的に:黒画面/画面オフ撮影、UI 偽装(他アプリに見せかける)、音量ボタンでの撮影、バックグラウンド撮影、タイマー連写 | **実装しない + 該当 API を使わないことのテスト**(§7) |
| **HC-3** | 画像およびその派生物を端末外に送信しない。アップロード動線・外部解析 API を持たない | CSP `connect-src 'self'` + ビルド時の依存監査 |
| **HC-4** | 「技術的にできるか」と「やってよいか」を UI・ドキュメントで分けて説明する。回避的ハックで制限を通さない | レビュー |

**無音撮影について**: 日本におけるシャッター音は法律ではなく業界の自主基準だが、
盗撮防止という背景がある。本アプリは無音を「静かな場所で書類を撮るための副次的性質」
として扱い、無音そのものを訴求点にしない。HC-1 / HC-2 はこの線引きを実装で固定する。

## 6. プラットフォーム制約(PWA でできないこと)

詳細と出典は `10-platform-findings.md`。ここには結論だけ置く。

| ID | 制約 | 対処 |
|---|---|---|
| ~~L-1~~ | ~~フル解像度の静止画が撮れない~~ | **取り下げ(D-017)。実機で 4032x3024 / 366dpi が取れた** |
| ~~L-2~~ | ~~torch(ライト)制御が不可~~ | **取り下げ(D-017)。`torch: true`** |
| L-3 | マニュアルフォーカス / 露出の制御 | `focusDistance` は min のみ。REQ-09 のブレ検出で代替する方針は維持 |
| L-4 | iOS standalone でカメラ権限が毎回聞かれる/黒画面になる既知バグ | REQ-15 の診断画面 + Safari タブで開く動線 |
| L-5 | Web Share **Target** は Android のみ | iPhone では「共有先」になれない。非対応として明記 |
| L-6 | File System Access API が iOS に無い | 「指定フォルダへ自動保存」は非対応 |
| L-7 | 端末内 OCR の現実的手段が乏しい | NG-01 |
| L-8 | iOS はインストールプロンプトが無く「共有→ホーム画面に追加」の手動のみ | 初回訪問時に手順を案内 |
| L-9 | EU 圏の iOS では standalone PWA が Safari タブで開く場合がある(DMA 対応) | 動作はするが表示形態が変わる旨を診断画面に表示 |
| L-10 | `ImageCapture.takePhoto()` はシャッター音を鳴らす可能性がある | 使わない(D-019) |
| L-11 | 12.2MP / 30fps を流し続けたときの発熱・電池・実 fps が不明 | U-11 で方式を決める |

## 7. Hard Constraint のテスト対応表

HC は文章だけでは溶ける。以下を対にして担保する(M1 で実装)。

| HC | ガード | テスト |
|---|---|---|
| HC-2 | 撮影は可視の `<video>` プレビューが表示されている時のみ許可する内部ガード | プレビュー非表示時に capture が拒否されることの単体テスト |
| HC-2 | `visibilitychange` で hidden になったらストリームを停止 | 同上 |
| HC-3 | CSP `connect-src 'self'; img-src 'self' blob: data:` | ビルド成果物に外部ホストが含まれないことの静的検査 |
| HC-3 | `fetch` / `XMLHttpRequest` / `sendBeacon` / WebSocket をコアから使わない | ソース走査テスト(許可リスト方式) |

## 10. 暫定値(Claude 提案・変更容易)

- 出力 DPI 既定: **200dpi**(A4 = 1654×2339px)
- Sauvola 窓サイズ: 画像長辺の **1/16**、k = **0.15**
- ブレ検出閾値(Laplacian 分散): **未定**(M2 で実測キャリブレーション)
- オートキャプチャの安定判定: 四隅が **500ms** 以上、**2%** 以内の移動に収まること
